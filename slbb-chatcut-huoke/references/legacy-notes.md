# 旧版问题记录（触发时读取）

以下来自 Desktop 0.5.16 与 2026-10 历史任务，不是所有版本的恒定定义。正常任务遵循当前 schema 和主流程，不预先修复。

- 改速叠字：旧版只改 playbackRate 会保持占位并扩大源范围。恢复原选段，同时计算速率与时长。旧记录推后 sourceIn、多删几秒凑总源时长不作通用修复，会改变内容。
- 小窗不同步：副本不保证跟随主轨，重算源范围/倍率/位置/时长。新版可能有分离的 linked audio，检查真实音频对象。
- 字幕重复/消失：先查目标工程、开关、字幕轨可见性与源覆盖。隐藏辅助字幕轨而非视频轨；不能认为所有 enable 都重建字幕。
- 空文本孤儿卡：旧版 set_card_text 置空会失去 token 关联，改回可能失败。不要以清空卡片隐藏字幕。
- maxLines 破坏：0.5.16 曾因该样式字段清空字幕和转写；保留禁用防线，分卡和画面验证行数，不在真实工程试险。
- 源纠错与 Script 冲突：旧任务在已写 Script 后改源报 Script row changes spoken words。应先纠错，刷新后重写 Script；读真实索引。仅已证实旧版不能安全改源时，最终字幕可非空显示修正并注明源未修，不能称源 ASR 修复。
- split_card invalid：旧版要求纯 token UUID，新版可能直接读 words[].id；按当前 schema，不永久强制去前缀。
- 横转竖裁切/越界：先查 crop、源旋转与字幕布局，新工程显式设画布；布局成功后看实际画面。

若确已字幕/转写丢失，先保存工程并检查主轨结构；未损坏不重剪。按现行自动修复流程恢复转写/字幕，源纠错完成后再校对卡片。重转写可能重新计费、改变分卡，记录真实耗时。历史重转写约 4 分钟、字幕 34.3 分钟只代表那次案例。
