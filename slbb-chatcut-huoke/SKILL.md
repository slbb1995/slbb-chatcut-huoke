# 获客口播剪辑

面向多个行业，当前宿主 AI 调用 ChatCut，把已有口播或讲解剪得清楚、自然、重点突出。以获客用途为主，兼容其他讲话类内容；不限时长，不强套营销结构，不自动批量剪多个作品。

用户当次要求优先，其次当前客户的已确认偏好，最后用下列默认值。无额外问卷、选模板或中途审核，只保留最终预览确认；必要输入无法判断时才问。

## 输入与默认值

- 主素材：一条主口播，可含已有镜头切换；用户明确属于同一条视频的连续主片段可合用。文件夹先辨认角色；用户授权自行选一条测试时直接选择并说明，不把其他主视频当 B-Roll。
- 文案可选：实际说出的内容为真相，文案辅助修正专名、数字和同音词，不补写未说的话。
- B-Roll 可选：按讲述节点选择能说明产品、过程或案例的现有素材，数量按需要，不凑画面。核对画面与所讲对象的关系，不把其他客户/项目画面冒充当前案例或效果；没有合适素材则保持主画面。
- 音乐可选：用户提供的优先，否则用 `assets/bgm.mp3`；明确不要就不加。输入已有字幕、标题、配乐或混剪时先识别，保留有用包装，避免重复叠加；烧录字幕不能当可编辑字幕删除。
- 默认输出：9:16、1080×1920、30fps、H.264 MP4，不附加 720P 副本。默认 1.15 倍速，明显过赶或失真时恢复原速并说明。
- 行业词表：开始时读 [术语与首次使用](references/terminology.md)。首次使用提醒上传或粘贴行业及客户话术、品牌/产品名和专业词，用真实资料填写并替换词表；未提供也可继续。逐句校对整片，不将当前客户词表套到其他客户，不凭近音互换名称。
- 顶部主题标题：把本条主题写清楚即可；优先用户文字，否则忠实概括，不编造卖点。字体、颜色、排版和衬底形式不固定，以清晰、协调、不遮挡重要画面为准。出现多久按内容和转折判断，不默认全程，也不固定 20 秒；具体规则见 [顶部标题](references/caption-quality.md#顶部标题)。已有合适标题沿用，用户说不要则不加。
- 字幕：简体、准确、完整、显眼，单行优先，每卡最多两行；按语义分卡，整卡在安全区内。外观不固定，不强制去标点。
- B-Roll 全屏期间同步真人小窗固定右上角，同一视频统一位置和尺寸，不自动切到左侧或随镜头移动。1080×1920 且有顶部标题时默认 300×533、left=744、top=340；其他画布按比例适配，放在标题下方。需要避让主体时优先调整 B-Roll 选段或构图；仅用户明确指定时改变小窗方位。没有真人主画面则不凭空制造小窗。辅助画面与小窗静音，只有主口播提供人声。

## 1. 连接、素材与转写

按当前工具 schema 确认连接与目标工程，不因旧接口缺失就判定能力不可用。新任务建独立工程并设画布；继续旧任务保留可恢复版本。每次调用传真实 projectId，旧宿主仅支持活动工程时先确认目标。连接细节见 [execution.md](references/execution.md)。

按需用 `scripts/ensure-chatcut.py --check` 做静态预检，不能代替连接验证；已有获准配置才用 `scripts/chatcut_mcp.py` 兜底。不安装、改配置、绕过权限、转交内置 Agent 或改走网页端；不调用图片/视频/音乐生成，普通文字标题可直接制作。

看元数据和代表画面，识别素材角色与已有包装，集中导入。仅转写需要的主口播，复用已有转写并等待原作业；本地操作不无条件等云上传。相关指南按阶段读，已授权或有默认值的事项不再追问。

任务目录用 `scripts/run_state.py init/start/end/event` 记录阶段、耗时和实际错误；已有状态继续使用。无终端则维护同样简短记录，不把辅助脚本当剪辑引擎。

## 2. 文案先行精剪与提速

先提取并通读完整口播文案，保留来源与时间对应，再确定删减和必要的局部顺句方案，随后落到视频剪切。原始转写、字幕纠错和建议删改稿分开；不为文字顺畅补入录音没有的新台词。用户已确认的删改稿就是本轮剪辑依据。正常任务由宿主内部完成文案分析；用户明确要求先看文案时才先交稿，不默认增加中途审核。

从已有讲话识别受众、问题、产品/服务价值、真实依据及行动提示，优先保留影响客户理解的信息；这些是取舍依据，不要求每条具备全部要素。不补原片没有的卖点、案例、价格承诺或引导话术。

优先删除明显口误、重复、卡壳及无实义的填充音、犹豫音、口头铺垫；口头词只有承担实际连接、强调或情绪表达时才保留，不以“个人语气”为由默认留下。无意义口气词须从音视频切除，不只删字幕；检查实际源边界，防止帧取整带回残音或削掉相邻字尾。自然气口另按下段保留。保留原意、事实、论据、数字、否定词、条件和叙事逻辑；局部调序记录原句对应，不让画面与讲话脱节。先靠精剪改善节奏，不靠继续提速掩盖冗余。

保留自然气口、字尾和必要的句间停顿，结合真实语音与操作节奏处理；停顿标记只用于定位，不等于纯静音，不清零短间隙、不统一压到某个秒数。字幕专名纠错在字幕层完成；只有明确要求修复源转写或错误影响剪切定位时才改源，避免为改字重做整条时间线。

机械清理可用原生能力；语义删减优先 Script：读取 → 集中编辑 → 应用 → 读回。按删改方案核对整段保留内容，再查接缝；有已确认文案时核对全文，不只检查几个关键词。完成主轨后再安排字幕、音乐和辅助画面；返修须同步受影响的字幕、标题时段、配乐长度和画面副本。

提速保持选中源内容不变，同时调整时间线占位，检查源范围、接缝和同步。不能只改倍率导致多读源，也不能移动下一段源起点或额外删有效讲话掩盖重叠。明显过赶则恢复原速。具体映射见 [execution.md](references/execution.md#倍速与视觉同步)。

## 3. 按需安排画面、字幕与声音

- **画面**：真人口播默认真人开头；产品展示、现场操作或屏幕讲解优先保留能说明问题的开场，不为真人开头重排内容。跨主轨切点拆分小窗，源范围、倍率和位置逐段匹配，主轨变化同步副本。集中修改，不并发写同一时间线。
- **字幕**：读 [caption-quality.md](references/caption-quality.md)。只取主口播音频为字幕源，B-Roll 期间继续显示。已有合格烧录字幕不重复生成。先完成源内容和剪切，再套一次模板、语义分卡和布局。不用空文本或裁字隐藏问题，不写旧版有破坏记录的 maxLines，按完整画面验收两行上限。
- **声音**：主动检查底噪、风声、嗡声和混响，用户明确要求降噪，或反馈未带麦且现场噪声大时，对全体主口播片段执行原生降噪，不因缺试听能力跳过已明确要求。录音干净则不机械处理；核对实际处理终态并提供同段前后对比，伤字音则恢复。默认人声为主，BGM 轻轻铺底，弱可闻即可，以听清内容、连续听不累为首要标准；不为证明配乐存在而提高音量。内置音乐默认从 -26dB、无额外 duck 起步，适用条件见[已确认音量参考](references/recovery-and-delivery.md#音频)；停顿和 B-Roll 期间不自动抬高音乐；更换录音或音乐后重点复核人声较轻的段落。音乐仍须实际进入混音、不爆音、不撑长视频。超长音乐裁到结尾，不足才自然循环并避开重复开场音效。降噪、循环与恢复按需读 [recovery-and-delivery.md](references/recovery-and-delivery.md)。

## 4. 总检与预览

检查实际剪切、源边界、接缝与自然气口，并逐句复核成片音轨中保留的口头词是否确有作用；删改方案已执行或字幕无残字，都不等于口气词已清干净。再查全片字幕的错漏/句意/专名/数字/断句及行数/安全区、标题实际时段、B-Roll 进出和小窗同步、降噪处理、BGM 混音及结尾画面。结构回读或再次转写不能代替看画面和听声音，无法检查的项如实标未验证。

提供工程定位、真实版本、时长、主要删减和预览。优先客户端播放；用户要测试结果或客户端预览不便时，可导出一次明确命名 preview_* 的测试预览，不冒充正式交付。记录 `run_state.py preview --revision <真实版本> --locator <位置>`，停在 awaiting_review。修改先 dirty，只改受影响部分并重新检查，不新增中途确认。

## 5. 确认后正式导出

用户确认当前预览后记录原话，执行 approve、gate。选择当前宿主真实的客户端导出能力（如 export 或旧版 local_export），追踪既有任务，不重复提交。只有确无可用能力时才说明手动导出办法。

剪辑与文件归档分开负责：本 Skill 接收当次目标路径完成导出，不绑定固定电脑目录，不顺带归档、同步或整理其他文件。位置已明确时直接执行；未明确时先完成剪辑和预览，在正式导出前一次问清。用户要求放回对应素材文件夹时，沿用该目录的实际命名与组织方式，交付处只新增最终成片；工程、转写、预览和检查资料留在工作目录。路径判定与交接见 [交付位置与职责边界](references/recovery-and-delivery.md#交付位置与职责边界)。

用 `scripts/verify_export.py <文件> --expected-duration <秒数> --decode` 检查默认格式与解码；用户指定其他规格时传入对应预期参数，见交付参考。再查实际画面与声音，技术通过不等于内容合格。正式验收后才 finish；成片用独立文件名，可按授权与素材同目录，不覆盖或删除原文件。

异常先读回，区分运行中、参数拒绝和真实失败；有依据、可逆的小问题自动修复、验证后接着剪，不因首次报错或缺参数直接停工。无新证据不重复同一失败调用；确实无法安全推进才保留工程并说明。转写时间越界等处理见 [recovery-and-delivery.md](references/recovery-and-delivery.md#自动修复与继续)，旧问题触发时才读 [legacy-notes.md](references/legacy-notes.md)。测试按 [validation.md](references/validation.md) 报告实际覆盖，不把文件检查当剪辑跑通或把一个宿主结果当其他宿主已通过。
